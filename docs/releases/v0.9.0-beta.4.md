# v0.9.0-beta.4: playback flow and retained-memory improvements

This beta addresses specific startup, cancellation and cleanup failures found
in a second review of the live acquisition and HLS paths.

- Live connections retain the most recent Choke/Unchoke state received before
  the peer's window metadata. A peer that already granted permission no longer
  needs to repeat it before the scheduler can request media. A subsequent Choke
  still prevents requests; handshake and media verification remain required.
- Stopping or expiring a direct compatibility playback session interrupts its
  pending source acquisition, including a same-source start-lock wait. A queued
  second viewer can proceed independently.
- The periodic idle reaper transfers retired-worker completion to the existing
  cleanup coordinator. A slow child-process shutdown no longer postpones later
  sweeps of unrelated idle sources. Explicit manager stop and engine shutdown
  still await their required cleanup.
- Completed HLS segments compact significant spare allocation before sharing
  storage with live playback and retained history. The accounting covers the
  actual retained allocation; the byte and duration limits are unchanged.
- Live segment lookup checks conversion from a 64-bit sequence offset to the
  platform index size, preserving lookup correctness on 32-bit targets.

These changes do not introduce permanent DVR, UTC programme catch-up or full
closed-engine archive compatibility. See [timeshift](../timeshift.md) for the
finite retained-HLS contract and [troubleshooting](../troubleshooting.md) for
source availability and player limitations. They do not guarantee instant
startup or smooth playback over an insufficient delivery path.
