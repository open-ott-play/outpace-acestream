# v0.9.0-beta.5: bounded startup and live progress recovery

This beta corrects lifecycle and live-delivery defects found after the
beta.4 deployment checks, and adds actionable continuity diagnostics.

- The startup prebuffer now keeps one deadline from the first nonempty media
  chunk. Repeated source gaps or PCR resets still discard stale data but cannot
  prolong the configured waiting limit. The live-head catch-up gate remains in
  effect, and retained chunk ordering and startup flags are preserved. Empty input
  does not grow the startup queue or consume a pending discontinuity marker.
- The live follower drains already-completed authenticated pieces after its
  cursor advances across an unavailable gap. Delivery no longer depends on a
  later network Piece message arriving to trigger that drain. Existing signature
  checks, access-point gating and consumer backpressure remain in effect.
- A full peer command queue no longer prevents a request from reaching another
  eligible peer. Admission is attempted before recording request ownership,
  while preserving request limits and existing retry ownership.
- Graceful HTTP shutdown closes source acquisition before waiting for continuous
  native and compatibility responses to finish. Pending source opens, same-source
  waiters, VOD resolution and range reads also observe shutdown. The VOD cache
  cannot publish a late resolution after the shutdown fence.
- HLS logs distinguish source events, receiver lag, transport markers, layout
  changes, clock resets and buffer-limit resets. Consecutive native resets are
  coalesced until the next segment. Normalized-audio recovery logs include the
  reason and generation transition.

The source changes include synthetic regression coverage for startup deadlines,
ready-piece delivery and shutdown with open streaming responses. Published CI
and deployed media checks must be assessed separately from those source tests.

No network binding, DNS policy, history budget or configured buffering target is
changed. These fixes do not guarantee instant startup: acquisition, live-head
catch-up, keyframe alignment and the player's buffers still matter. Replay
remains finite retained-memory history, not persistent DVR or general upstream
archive access. See [timeshift](../timeshift.md) and
[troubleshooting](../troubleshooting.md).
