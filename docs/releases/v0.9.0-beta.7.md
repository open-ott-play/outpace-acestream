# v0.9.0-beta.7: bounded startup and reliable session teardown

This beta fixes source lifecycle and media delivery edge cases:

- Native HLS and compatibility manifest requests apply one startup timeout to
  source acquisition and response preparation. Discovery or a queued opener can
  no longer wait indefinitely before the playlist timer starts. Expiry returns
  HTTP `503` with `Retry-After: 1`; cancellation releases unpublished playback
  leases without revoking another viewer's lease.
- Stopping a stream or tearing down its manager
  explicitly cancels source consumption even when callers retain session handles.
  Receivers may drain their queued data before observing EOF.
- A source that ends cleanly with fewer than the configured startup segments can
  expose its completed current-generation media as a finite HLS playlist. Incomplete
  tails, unfinished source catch-up, old recovery generations and terminal failures
  are not promoted. Finalized media cannot grow again, and its unused assembly
  buffer is released.
- VOD downloads reissue outstanding block requests when a peer resumes after
  choking. Received coverage, request credits and progress deadlines are preserved;
  duplicate Unchoke messages do not resend the queue again.

Regression coverage uses synthetic sources, paused clocks and in-memory peer
sessions. The normal workspace, lint, source-packaging and media acceptance gates
remain required. These checks do not claim universal live-channel availability or
device compatibility.

No network binding, DNS policy, authentication, history budget or runtime default
is changed. Retained replay is still bounded in-memory history, not a persistent
or UTC-indexed archive. Beta publication does not replace the stable release or
the container `latest` channel. Deployments must select the new image explicitly;
keep the previous image digest and deployment configuration available for rollback.
