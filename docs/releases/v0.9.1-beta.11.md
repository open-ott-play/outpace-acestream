# v0.9.1-beta.11: consistent native AAC selection

`OUTPACE_HLS_AUDIO_LANGUAGE` accepts an ordered, comma-separated list of
three-letter language tags, such as `eng,rus`. The native AAC classifier and HLS
packager use the same selection. The setting is fixed for the engine instance:
one viewer cannot change the audio track of another viewer's shared stream.
An unset preference preserves deterministic selection by the programme's PMT
order, preferring primary audio over accessibility tracks when available.

Rust library users constructing `HlsAudioConfig` directly must set the new
`preferred_languages` field or use `..Default::default()`.

The selection applies to native and compatibility HLS, with or without audio
normalization. The strict normalization classifier also rejects contradictory
stream-type and codec descriptors. Normalized AAC passthrough now filters the
unselected audio packets as well as their PMT entries, keeping the advertised
track and segment payload consistent. Language preferences do not select AC3/MPEG
audio by language, enable LATM AAC, or affect raw TS, VOD or origin HLS. They do
not make the retained replay archive persistent.

Loading a broadcast signing identity rejects RSA keys too short to contain the
complete PKCS#1 v1.5 SHA-1 encoding. Existing key generation and wire algorithms
are unchanged. Fixed-size AES key and IV initialization uses their known lengths
directly.
The transport-format documentation now explicitly describes its fixed public
constants and lack of confidentiality or authenticity; the encoding is unchanged.

Shared fuzz and security workflow references advance together. The source RC
continues to require all six configured fuzz targets and the existing synthetic
media checks before release.

This release retains beta.10's bounded VOD startup and shared store ownership
fixes. Listener, bind, seeding and cache-path defaults are unchanged. Stable and
container `latest` channels remain on their prior release.
