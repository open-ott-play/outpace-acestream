# v0.9.1-beta.14: origin diagnostics and connection reuse

Managed origin HLS preserves the upstream HTTP status when an origin rejects a playlist or media request. The gateway retains its existing error status contract and adds a numeric `X-Outpace-Upstream-Status` header, with distinct sanitized error codes for authentication, authorization, missing or removed resources, rate limiting and temporary unavailability. Origin URLs, response bodies and credentials are not exposed in these diagnostics.

Finite origin requests reuse a bounded pool of HTTP/1 connections after fresh URL and DNS validation. The pool retains at most sixteen client entries with one idle connection per client, a fifteen-second idle timeout and a sixty-second client lifetime. Each entry is isolated by transport policy, origin authority and the approved resolved endpoint. Changed DNS pins retire previously stored clients for that authority; active requests retain their existing approved destination until completion or cancellation.

Request deadlines, cancellation, redirect validation and memory admission limits remain enforced. Continuous source downloads keep their existing transport path. This change introduces no additional dependency and does not enable prefetching, ambient proxies, cookies or relaxed TLS verification. Reqwest policy retries remain disabled. Hyper may transparently reopen an unusable reused connection only before the request starts writing; failed or partially received responses are not replayed.

The design review included the MIT-licensed [MediaFlow Proxy](https://github.com/mhdzumair/mediaflow-proxy) and [MediaFlow Proxy Light](https://github.com/mhdzumair/mediaflow-proxy-light). The implementation is written for Outpace's existing guarded transport and remains AGPL-3.0-or-later.
