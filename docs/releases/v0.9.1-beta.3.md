# v0.9.1-beta.3: typed sources and playback contracts

This beta distinguishes live swarms, single-file VOD and origin HLS before choosing
playback behavior. Origin HLS works through native stream redirects, compatibility
handoff and explicit CLI `play --resolve`. Direct JSON carries `is_direct: true`,
preserves the original signed URL and does not invent engine-owned controls or
history. Unresolved metadata stays unknown instead of claiming live content.

Concurrent catalog resolution shares in-flight work with bounded bookkeeping and
cancellation ownership. Completed signed origin URLs are not retained indefinitely.
Live discovery retries an initially completed empty run once within the original
ten-second budget, preserving late peer delivery and cleanup.

VOD raw ranges retain arbitrary verified bytes. The experimental VOD HLS path now
requires aligned MPEG-TS, rejects unsupported containers before advertising media,
validates streamed packets and bounds probe time and playlist geometry. Its
byte-based durations remain nominal; this does not add GOP indexing or MP4/MKV
remuxing. H.264/HEVC keyframe detection now examines validated PES elementary
payload, preventing false access points in optional headers and trailing bytes.

Qualification includes deterministic source, client-contract, catalog lifetime,
discovery, VOD failure and media access regressions. Synthetic media seeds also
exercise keyframe gating in the existing media fuzz target. Release-candidate
assessment requires normal CI, security analysis and all four fuzz campaigns on
the same source. Archive and container publication retain complete corresponding
source and the existing seven-binary/three-container-platform verification.

Origin handoff delegates HLS interpretation and buffering to the player. Managed
HLS acquisition, hybrid HLS-over-P2P, full original `liveseek` semantics, multi-file
VOD and persistent UTC programme archives remain outside this beta. Existing
retained replay remains an Outpace extension with per-viewer generations.

This prerelease advances the `beta` container channel and does not replace stable
`latest`. Use versioned artifacts and retain the preceding verified deployment
configuration and image digest for rollback. See [source resolution](../source-resolution.md)
and [retained replay](../timeshift.md) for the exact support boundary.
