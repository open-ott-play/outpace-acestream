# v0.9.1-beta.5: HLS cache continuity and truthful metadata

Repeated identical origin playlists now preserve fresh media cache entries.
Changes to the playlist or resolved resource identities invalidate the cache;
in-flight older responses cannot repopulate a newer generation. Media freshness
still follows the original response headers and the existing thirty-second cap.
A rollback of the discontinuity sequence also starts a new resource identity
epoch, even if the media sequence keeps increasing. Invalid, duplicated,
misplaced or overflowing discontinuity sequences are rejected before publication;
ordinary sliding updates preserve overlapping resource URLs.
Resource-bearing interstitial date ranges are explicitly unsupported, so asset
URLs cannot bypass the managed relay's ownership. Ordinary date ranges remain
unchanged. Explicit initialization-map byte ranges remain the supported subset.

The origin playlist parser now lives in the dependency-free `ace-media` crate.
The engine and a fifth mandatory RC fuzz target use that same parser and bounded
rewriter. Synthetic seeds cover master/renditions, fMP4 byte ranges, discontinuity,
date ranges and malformed ranges; fixed corpus replay also runs on ordinary PRs.
Stateful acquisition, cancellation, replay and decoded media retain their separate
tests. Parser fuzzing does not establish original-engine equivalence.

Compatibility status now includes admitted managed-HLS playbacks, rather than
reporting idle while a relay viewer is active. Native sessions remain shared
source counts; the combined number is not a uniform viewer count. Numeric version
codes retain the patch component of beta/RC/build versions.

Standard single-file metainfo preserves its advisory UTF-8 `info.name` through
VOD resolution and `get_media_files.filename`. Names are limited to 4,096 bytes
and omit invalid, empty or control-containing input without altering the exact
infohash or verified geometry. A filename is display metadata, not a trusted
filesystem path. Unknown MIME, legacy live filenames and HLS file tables are
still omitted rather than inferred.

This release does not add original Ace `liveseek`, multifile playback, hybrid
HLS-over-P2P or persistent UTC recording. Managed origin HLS still has no retained
archive. See [source resolution](../source-resolution.md),
[replay](../timeshift.md) and [RC fuzzing](../fuzzing.md).

Only the beta channel advances; stable release and container `latest` are unchanged.
