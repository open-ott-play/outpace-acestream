# v0.9.1-beta.6: managed-origin replay and SDK playback compatibility

Managed-origin HLS now has opt-in retained replay for a bounded, declared-independent
MPEG-TS subset, with table and access-point checks. Completed segments are indexed
in manifest order even when fetches finish out of order. Seeking returns a finite immutable playlist;
failed seeks preserve the previous view and successful transitions revoke old
replay generations. Retained media can play after the origin removes its copy.
Another viewer and the original live playlist remain independent.

This uses the existing `OUTPACE_HISTORY_SECONDS`, `OUTPACE_HISTORY_BYTES` and
`OUTPACE_HISTORY_TOTAL_BYTES` settings. History remains disabled by default. If
managed HLS and history were already enabled, eligible origin viewers now share
the same global retention budget as native HLS packagers. There is no background
acquisition. Master/rendition playlists, fMP4, byte-range media and audio-only
origins are outside this first replay subset; supported live relay paths remain
available. See [the exact contract](../timeshift.md#managed-origin-ts-replay).

The documented `/hls/manifest.m3u8?manifest_url=...` gateway now admits direct
HTTP(S) manifests with the existing compatibility and managed-HLS gates. It uses
the relay's bounded fetch policy, URL validation and viewer ownership.

Playback source parsing accepts identical decoded source-selector duplicates
emitted by the Android SDK's URL builder. Conflicting source values and duplicate
command/options parameters are still errors. Signed query bytes inside an origin
URL remain intact.

Regression coverage includes HTTP control/state transitions, capture gaps,
out-of-order completion, memory accounting, cancellation, expiry, independent
viewers and generated-video decoding. The parser's retained-segment metadata is
also checked by the mandatory HLS RC fuzz target.

These are documented compatibility routes and Outpace replay extensions, not a
claim of complete original-engine equivalence. Original Ace `liveseek`, hybrid
HLS-over-P2P, multifile playback and persistent UTC programme archives remain
separate work. Device-specific archive menus still require player integration.

Only the beta channel advances; stable releases and container `latest` stay unchanged.
