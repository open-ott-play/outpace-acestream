# v0.9.1-beta.7: replay continuity and magnet selection

Managed-origin TS replay preserves completed segment downloads across overlapping
playlist refreshes and sliding live windows. A download is associated with its
original retained descriptor, so a routine cache refresh cannot create a hole in
the archive. Source resets, replaced descriptors, expired retention and stopped
sessions still prevent stale work from publishing. Segment validation runs
outside the session state lock, with ownership checked again before publication.
The HTTP cache and retained history account for backing buffer capacity, including
unused allocation space, rather than treating payload length as the allocation.

Magnet parsing now examines the whole selector set and decodes query parameters.
Equivalent hexadecimal or base32 v1 topics may repeat; conflicting topics and
unsupported file-selection intent fail explicitly. A later parameter cannot
silently change which content or file the caller requested. This is Outpace's
documented selection policy, not a claim of complete original-engine parity.

The existing history settings and default-off behavior are unchanged. This
release does not add fMP4, master/rendition or audio-only retained replay,
persistent recording, UTC programme archives or original Ace `liveseek`
semantics. Supported live HLS relay formats remain available. See
[retained replay](../timeshift.md#managed-origin-ts-replay) and
[source resolution](../source-resolution.md).

Only the beta channel advances. Stable releases and the container `latest`
channel remain unchanged.
