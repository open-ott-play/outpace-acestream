# v0.9.1-beta.8: identity dependency compatibility

The engine upgrades Ed25519 signing to ed25519-dalek 3 while retaining the same
32-byte identity seed format, public node identities and handshake signature
format. New identities obtain their seed directly from the operating system
random source. RSA retains its compatible random-number interface. Existing
identity files require no conversion or replacement.

Regression coverage checks deterministic public identities, generated-key
restoration, persisted seed bytes, signature consistency and private Unix file
permissions. An independent RFC 8032 known-answer test pins both the public key
and signature bytes. Both workspace and fuzz dependency locks include the upgrade.

The shared security and release-candidate fuzz workflows use the updated pinned
CI toolkit. The source release candidate continues to require the normal test
suite, synthetic HLS and retained-replay decoding, security checks and all five
fuzz targets.

The retained-replay scope and runtime defaults remain as documented in
[time-shift support](../timeshift.md). This maintenance release adds no new
archive formats, persistent DVR or original-engine protocol guarantees.

Only the beta channel advances. Stable releases and the container `latest`
channel remain unchanged.
