# v0.9.1: managed origin HLS and retained replay

This stable release promotes the functionality qualified through the 0.9.1
beta series. The promotion changes package versions and documentation; the
engine implementation is unchanged from beta.14.

## Playback and compatibility

- Optional managed origin HLS supports TS and fMP4 resources, final-redirect URL
  resolution, strict byte ranges, and bounded gzip decoding for playlists.
- Finite origin requests reuse bounded, DNS-pinned HTTP connections. Each request
  and redirect still validates its destination; deadlines and memory limits
  remain enforced.
- Origin failures expose a sanitized error code and numeric
  `X-Outpace-Upstream-Status`, while retaining the gateway's existing HTTP error
  contract. Signed source URLs and credentials are not returned in diagnostics.
- Descriptor selection and the supported SDK playback/stop contracts handle
  additional source forms without treating content IDs and infohashes as
  interchangeable selectors. See the [compatibility matrix](../protocol/compat-matrix.md).
- VOD startup, shared storage ownership, cancellation, and worker shutdown have
  additional bounds and regression coverage.

## History and audio

- Managed origin HLS can retain a bounded local replay window. Independent
  viewers can seek within retained media without moving another viewer.
- Retained replay is opt-in and finite. It is not a durable DVR or a guarantee
  of a programme archive supplied by every source. See [timeshift](../timeshift.md).
- Native AAC selection supports the instance-wide `OUTPACE_HLS_AUDIO_LANGUAGE`
  preference. Shared streams keep one consistent selection; independent
  per-viewer language switching is not introduced.
- The [audio inventory tool](../../tools/audioscan/README.md) supports inspection
  and comparison while preserving sessions on an existing daemon.

## Upgrade and qualification

Existing listener, seeding, placement, and storage defaults are preserved. Optional
features retain their explicit configuration requirements. Rust library callers
constructing `HlsAudioConfig` directly must set `preferred_languages` or use
`..Default::default()`.

The release process runs the source RC gates, including all six configured fuzz
targets and synthetic media/replay checks, on the exact release commit. Published
packages include matching source, dependency inventories, and license notices.
Use [installation](../installation.md), [containers](../containers.md), or
[Kubernetes](../kubernetes.md) for the 0.9.1 recipes. Verify checksums and pin the
published image digest for an operational deployment.
