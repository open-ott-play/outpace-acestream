# Outpace 0.9.5-beta.1

This beta tightens retained-history memory accounting and peer metadata assembly.

- Native HLS replay bytes retain their global history-budget charge until the
  final response clone or slice is dropped. Pruning a history entry or stopping
  its store no longer admits replacement history while a client still holds that
  allocation. History wrappers preserve the original bytes without copying;
  live playback keeps its independent retention behavior.
- Peer metadata blocks must have the exact expected length and a matching
  declared total size. Identical duplicates are harmless; conflicting duplicates
  fail without overwriting accepted data. Piece indices are checked before
  conversion on 32-bit targets.
- Metadata requests use the peer's advertised extension ID, while responses
  must use our advertised ID. Unrelated extensions cannot supply metadata or reject its requests. Disabled
  extension IDs are rejected.
- The metadata seeder uses the client's advertised reply ID and applies later
  enable/disable mapping updates. Negative or overflowing block indices cannot
  alias the first block or panic while calculating an offset.
- FFmpeg preflight tests restore temporary environment variables even after an
  assertion failure. A controlled clock verifies capability ordering and the
  shared aggregate deadline; separate real-child tests retain timeout and
  process-cleanup coverage. Production timeout values are unchanged.

The internal Rust `PeerSession::fetch_metadata` API now takes the locally
advertised extension ID as a separate argument. Downstream source callers must
provide it after exchanging the extended handshake. HTTP playback APIs and
existing deployment settings are unchanged.

Regression coverage includes retained one-byte replay slices, store destruction,
metadata block geometry, advertised sizes, duplicate replies, directional
extension IDs, mapping updates and oversized piece indices. The source RC runs the full Rust,
media, native macOS, security and six-target fuzz qualification before the
release tag. Binary and container verification follows publication separately.

Retained history remains bounded local replay. Available coverage depends on
received media; this beta does not introduce persistent DVR or provider archives.
