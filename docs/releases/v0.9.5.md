# Outpace 0.9.5

This stable release consolidates the 0.9.5 beta series: stricter peer metadata,
accurate retained-history ownership, and bounded live scheduling and recovery.

## Playback and scheduling

- Equal-capacity scheduling keeps narrow peer coverage useful instead of
  stranding slots that a broader peer can cover later.
- Up to 100 accepted whole-piece service intervals refine otherwise equal peer
  choices. Fresh timing is required for every tied candidate; unknown timing
  preserves deterministic fallback. Retries, mixed contributors, duplicates and
  partial bytes retained across reconnects cannot teach misleading speeds.
- The shared request floor advances immediately after contiguous media drains,
  suppressing obsolete queued chunks before downstream backpressure can stall
  publication. A wire write already underway may complete.
- Immediately-ready empty source reads cooperate with cancellation and deadlines.
  An expired startup deadline releases buffered media before consuming a ready
  discontinuity from the next source epoch.

## Memory and metadata correctness

- Retained HLS history stays charged to its global byte budget until the last
  response clone or slice is dropped, even after history pruning or store shutdown.
- Metadata blocks require exact lengths and matching declared sizes. Conflicting
  duplicates fail without overwriting accepted data; oversized piece indices
  cannot alias a valid block or overflow arithmetic on 32-bit targets.
- Metadata acquisition and seeding honor directional extension IDs and later
  mapping updates. Unrelated or disabled extensions cannot supply metadata or
  reject its requests.
- FFmpeg preflight tests use controlled time for sequence/deadline assertions
  while separate real-child cases retain process timeout and cleanup coverage.

## Compatibility and qualification

HTTP APIs, production timeouts and existing runtime configuration remain
unchanged. The internal Rust `PeerSession::fetch_metadata` API now requires the
locally advertised extension ID separately; downstream source callers must
supply it after the extended handshake.

Release acceptance includes the exact-source RC with six mandatory fuzz targets,
seven native binary/source pairs and the three-platform container index.
The [release workflow](../releasing.md) defines publication and verification.
Beta notes retain the change history:
[beta.1](v0.9.5-beta.1.md) and [beta.2](v0.9.5-beta.2.md).

This release does not claim measured startup acceleration on real channels,
complete original-engine parity, persistent DVR or provider archives. Timing
refines equal-priority candidates, not a global minimum-ETA policy. Runtime gaps
do not restart global buffering for all viewers. The reconstructed native
algorithms and remaining limits are documented in
[protocol note 74](../protocol/notes/74-native-live-recovery.md).
